# Rasel audit (baseline commit b21062e)

Severity: **H** high, **M** medium, **L** low. Every row is addressed by a commit in this series unless marked "accepted".

| 1 | H | Concurrency | Verify is read-modify-write with no concurrency control: two parallel correct verifies can both return a token (replay), and parallel wrong guesses can exceed `MaxAttempts` because each reads the same `Attempts`. | `OtpHandlers.cs:114-120` (`GetAsync` -> `Attempt` -> `UpdateAsync`), `Repositories.cs:72` (blind `SaveChanges`), `RaselDbContext.cs:22-24` (no concurrency token) | Version concurrency token + retry loop |
| 2 | H | Concurrency | Two concurrent OTP requests for the same phone both pass the cooldown check and both create Active challenges. | `OtpHandlers.cs:28-31`, `:49-52` | Filtered unique index (one Active per client/phone/purpose); conflict mapped to 429 |
| 3 | H | Reliability | Outbox is an in-memory `Channel`; message text is never persisted, so a crash/restart leaves rows `Queued` forever and loses the message. No retry for transient failures. | `MessagingServices.cs:39`, `MessageSender.cs:14-27`, `Message.cs:5` | Durable DB outbox, lease, retry with backoff, body cleared once terminal |
