# راسل: الحالة الحالية وخطة التطوير

> Powered by Kandil Smart Digital Solution

مكتوب لصاحب المشروع بلغة بسيطة. كل بند فيه حالة تحقق صادقة:
**تحقق حي** = اتجرب فعليًا على تشغيل حقيقي، **اختبار آلي فقط** = الكود مغطى باختبارات لكن ما اتجرّبش على واتساب حقيقي، **لم يُختبر** = مكتوب ولم يُشغَّل.

## أولًا: ما تم إنجازه

| البند | الحالة |
|---|---|
| الواجهة البرمجية (إنشاء جلسة، QR، إرسال نص لرقم أو جروب، متابعة حالة الرسالة) | اختبار آلي + تشغيل محلي بمحرك وهمي (Fake). إرسال حقيقي لجروب اتجرّب مرة واحدة على الجسر الأصلي |
| منع تكرار الإرسال (Idempotency-Key) | تحقق بتشغيل محلي + اختبار آلي |
| الـ OTP (طلب وتحقق، حد المحاولات، انتهاء الصلاحية) | رفض الكود الغلط والقفل اتجرّبوا؛ مسار النجاح اختبار آلي فقط |
| مفاتيح API بصلاحيتين (Admin وStandard) وإنشاء/إلغاء/تدوير المفاتيح | اختبار آلي (قائمة 1 في TEST-CHECKLIST لم تُعلَّم بعد) |
| وضع Managed: راسل يجهّز ويشغّل ويراقب المحرك بنفسه، محرك مستقل لكل رقم | اختبار آلي بمشغّل وهمي؛ التشغيل الحي مع واتساب حقيقي جزئي |
| تعدد الأرقام (حد أقصى، منفذ ومجلد وتوكن لكل جلسة) | اختبار آلي؛ لم يُجرَّب بمسح QR لرقمين حقيقيين |
| حدود الاستخدام (يومي، لكل مستلم، لكل مفتاح، تباعد عشوائي بين الرسائل) | اختبار آلي + بعضها تحقق محلي |
| لوحة الإدارة (عربي/إنجليزي، فاتح/داكن، الجلسات، الإرسال التجريبي، الصحة) | اختبارات آلية + لقطات شاشة؛ تجربة على واتساب حقيقي ناقصة |
| الـ Webhooks (إشعار عند نهاية الرسالة، موقّع) | قراءة كود فقط، لم يُستلم أي إشعار فعليًا |
| Docker وسكربتات التثبيت (Windows service) | **لم تُنفَّذ قط** |
| وثائق (API، دليل التكامل، دليل المستخدم، openapi.json مع اختبار تزامن) | تحقق بالاختبارات |

## الفجوات المعروفة (بصراحة)

1. لا يوجد endpoint لعرض كل الجلسات (القائمة تعتمد على ما يحفظه المتصفح).
2. خطوات تجهيز المحرك تظهر بالإنجليزي في الصفحة العربية.
3. مجلد الجلسة القديم الواحد (`session`) لا يُنقل تلقائيًا؛ لازم إعادة ربط الأرقام.
4. Docker والسكربتات لم تُشغَّل، وتسجيل المهمة المجدولة لم يُختبر.
5. الـ Webhooks بمحاولة واحدة بلا إعادة محاولة.
6. التسليم "مرة على الأقل" (at-least-once): قد تتكرر رسالة نادرًا عند انقطاع في توقيت سيئ.
7. عقدة واحدة فقط (SQLite): لا توسّع أفقي ولا HA.
8. الإرسال/OTP الحقيقي عبر محرك راسل نفسه لم يُتحقق بعد.
9. تجربتك على الجروب فشلت لأن الرقم المرسِل ليس عضوًا في الجروب (الكود `group_not_found_on_session`)؛ أضِف الرقم للجروب وأعد المحاولة.

## ثالثًا: كيف تستخدم الـ APIs (باختصار)

المرجع الكامل: [API.md](API.md) | [INTEGRATION.ar.md](INTEGRATION.ar.md) | [examples/](examples/). كل الطلبات تحتاج الهيدر `X-Api-Key`. الأمثلة تفترض العنوان `http://localhost:5190` والمفتاح المحلي `$KEY`.

```bash
H="X-Api-Key: $KEY"

# إنشاء جلسة (رقم) ثم متابعتها
curl -H "$H" -H "Content-Type: application/json" -d '{"name":"رقم1"}' http://localhost:5190/v1/sessions
curl -H "$H" http://localhost:5190/v1/sessions/<sessionId>          # الحالة
curl -H "$H" http://localhost:5190/v1/sessions/<sessionId>/qr       # QR للمسح

# إرسال نص لرقم (Idempotency-Key يمنع التكرار)
curl -H "$H" -H "Content-Type: application/json" -H "Idempotency-Key: order-1001" \
  -d '{"phone":"+20XXXXXXXXXX","text":"مرحبا"}' http://localhost:5190/v1/messages

# إرسال لجروب (الرقم المرسِل لازم يكون عضوًا فيه)
curl -H "$H" -H "Content-Type: application/json" -H "Idempotency-Key: grp-1" \
  -d '{"groupName":"اسم الجروب","text":"مرحبا"}' http://localhost:5190/v1/messages

# متابعة حالة الرسالة (Queued ثم Sent أو Failed)
curl -H "$H" http://localhost:5190/v1/messages/<messageId>

# OTP
curl -H "$H" -H "Content-Type: application/json" -d '{"phone":"+20XXXXXXXXXX","purpose":"login","language":"ar"}' http://localhost:5190/v1/otp/request
curl -H "$H" -H "Content-Type: application/json" -d '{"challengeId":"<id>","code":"123456"}' http://localhost:5190/v1/otp/verify
```

الـ Webhooks (اختيارية): فعّل `Webhooks__Enabled=true` و`Webhooks__Url` و`Webhooks__Secret`؛ يصلك POST عند نهاية الرسالة بتوقيع `X-Rasel-Signature` (انظر القسم 9 في API.md ومثال `examples/verify-webhook.ts`). استمر بالاستعلام عن `GET /v1/messages/{id}` كمصدر الحقيقة.

## رابعًا: كيف ترجع وتكمل

```powershell
# 1) تشغيل الـ API في وضع Managed (من مجلد المشروع)
$env:WhatsApp__Provider="Managed"
$env:Seed__DevApiKey="<مفتاح لا يقل عن 24 حرفًا>"
$env:Cors__AllowedOrigins__0="http://localhost:4300"
dotnet run --project src/Rasel.Api --urls http://localhost:5190

# 2) بناء لوحة الإدارة
cd admin; npm ci; npm run build      # الناتج في admin/dist

# 3) الاختبارات
dotnet test Rasel.sln; (cd admin; npm test); (cd sidecar; npm test)
```

* أول تشغيل في Managed يحتاج Node.js 18+ واتصال إنترنت (يُنزّل مكتبات الواتساب وChrome).
* المفتاح المحلي المستخدم في التجارب `rasel-dev-key-local-0004` **للتطوير فقط، غيّره في الإنتاج** (`Seed__DevApiKey` يعمل فقط على قاعدة بيانات فارغة؛ أنشئ مفاتيح جديدة عبر `POST /v1/keys` وألغِ القديم).
* خطوات الاختبار الحي مع واتساب الحقيقي في [TEST-CHECKLIST.ar.md](TEST-CHECKLIST.ar.md) (ما زالت غير مُعلَّمة).
